# 个人知识库与技术方案生成规范

1. **方案结构标准**：所有技术方案必须包含【背景与目标】【架构设计（附 Mermaid 图）】【核心接口与表结构】【风险与降级预案】四个章节。
2. **知识库联动规则**：每次生成新文档前，先检索 `01-Tech-Specs` 和 `02-Troubleshooting` 目录，若存在关联历史文档，必须在文末用 `[[文档名]]` 建立双向链接。
3. **自动归档规则**：整理草稿时，统一在文档顶部补充 YAML 标签（`tags` 和 `date`），再移动到对应分类目录。
4. **纠错记忆库**：（以后每次修改了 AI 的输出偏好，就让它把新规则追加到此条下方）

5. **自动推送规则**：方案文档修改完成后，自动执行 `git add . && git commit -m "docs: 完成归档" && git push`，确保变更及时归档到仓库。
6. **自动化学习与智能归档工作流**：当用户发送类似"这是我的学习笔记，你学习一下"、"把这个归档进知识库"或将新草稿放入 `00-Inbox/` 并要求学习时，自动触发以下标准作业程序（SOP）：

   - **步骤一 · 领域识别与动态目录管理**：先扫描当前知识库根目录结构（包含 `00-Inbox`、`01-Tech-Specs`、`02-Troubleshooting`、`03-Templates-Prompts`），根据笔记核心主题判断所属领域与内容属性：
     - 若属于**技术方案、系统架构、课程笔记或知识地图**，归入 `01-Tech-Specs/`；该领域笔记逐渐增多时，自动在目录下创建清晰的子分类文件夹（如 `01-Tech-Specs/Linux运维/`、`01-Tech-Specs/广告投放/`、`01-Tech-Specs/AI与RAG/`）。
     - 若属于**报错记录、踩坑复盘、排错指南**，归入 `02-Troubleshooting/`。
     - 若属于**可复用命令速查表、提示词模板、标准化清单**，归入 `03-Templates-Prompts/`。
     - 遇到全新跨界大领域（现有顶级目录无法合理容纳），可在征求用户一句话确认或遵循 `04-领域名称` 编号规范的前提下新建顶级分类目录。

   - **步骤二 · 内容清洗与结构化内化**：保持用户原始笔记核心知识点与命令代码完整不丢失；自动为笔记补充标准头部信息（包含：所属领域、核心摘要、关键标签、创建/更新日期），优化 Markdown 标题层级与排版；若一篇长笔记同时包含"原理方案"与"高频命令速查"，可智能拆分为主文档与速查模板分别归档，并在文末互相添加关联链接。

   - **步骤三 · 清理收集箱与索引同步**：若该笔记最初来自 `00-Inbox/`，归档完成后自动删除 `00-Inbox/` 中的原始草稿；若对应领域存在"知识地图/索引文件"，自动将新笔记链接追加进去。

   - **步骤四 · 强制异地双备份**：全部文件写入与整理完成后，必须立即在终端执行 `git add . && git commit -m "docs(领域): 新增/归档《笔记标题》"` 推送至仓库，确保变更及时归档。
